## このリポジトリについて

架空のうどん店「**うどん処 まつかぜ**」のサイトを題材に、GitHub の使い方を練習します。

**わざと「改修依頼が出そうな状態」にしてあります。** セッション中に、あなたが依頼を Issue として書き、AI に実装させ、差分で確認する流れを体験します。

---

## 使い方（当日の最初にやること）

### 1. このリポジトリを自分のアカウントに複製する

このページ上部の緑色のボタン **「Use this template」→「Create a new repository」** を押します。

- リポジトリ名: `wpmeetup-vol33-practice`（好きな名前でOK）
- 公開設定: **Private** を選んでください
- 「Create repository」を押す

> 💡 **Fork ではなく Use this template を使います。** Fork だと元のリポジトリと繋がったままになり、練習には不向きです。

### 2. できあがったリポジトリで作業する

以降のハンズオンは、**あなたのアカウントにできたリポジトリ**で進めます。

### 🔍 `site/index.html` と `docs/店舗情報.md` を見比べてみてください

**食い違っているところがあります。** それが最初の Issue のネタになります。

## ハンズオンの流れ

| # | やること | 使うもの |
|:--|:--|:--|
| ① | Issue を書く | ブラウザ |
| ② | Projects に並べる | ブラウザ |
| ③ | クローン → 編集 → コミット → 同期 | VS Code |
| ④ | Issue を AI に渡して、差分で確かめる | VS Code + AI |

**①②はブラウザだけで完結します。** VS Code の準備が間に合わなくても、ここまでは全員参加できます。

## 本物の案件でやるときは

このリポジトリはプレーンな HTML / CSS ですが、**置き換えて考えれば、そのまま実務で使えます。**

| 練習用 | 本物の WordPress 案件だと |
|:--|:--|
| `site/style.css` | 子テーマの `style.css`、テーマの SCSS |
| `site/index.html` | テンプレートファイル、ブロックパターンの定義 |
| `docs/店舗情報.md` | 原稿、仕様書、AIへの指示ファイル（`CLAUDE.md` など） |
| Issue | クライアントからの改修依頼 |
| Projects | 複数案件の横断管理 |

> ⚠️ **WordPress のファイル一式をまるごと入れるのは推奨しません。**
> `wp-config.php` には DB のパスワードが入っています。`.gitignore` の設定を必ず確認してください（`handouts/` 参照）。
