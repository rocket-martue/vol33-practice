# 差分チェックリスト — AIの出力を確認する

AIが書いたものを、**そのまま入れない。** 差分を見てから採用します。

> **コードが読めなくてもできます。** 見るのは「何が変わったか」であって「コードが正しいか」ではありません。

---

## 🟢 全員やる — 3点チェック

### ① 頼んでいないファイルを触っていないか

変更されたファイルの**数と名前**を見ます。

- 「CSSの色を変えて」と頼んだのに、HTMLも変わっている → 🚩
- 見覚えのないファイルが増えている → 🚩

> AIは「ついでに整えておきました」をやります。**悪気なくやるので、こちらが見るしかありません。**

### ② 頼んでいない行を消していないか

**赤い行（削除）を重点的に見ます。**

- コメントが消えている → 🚩
- 関係ない設定が消えている → 🚩
- 空行やインデントだけが大量に変わっている → 🚩（本当の変更が埋もれるので、差し戻したほうがいい）

> 「書き直し」をお願いすると、既存の記述がまとめて落ちることがあります。**一番よくある事故です。**

### ③ 意図と違う実装になっていないか

**Issue に書いた「どうなってほしいか」と見比べます。**

- 頼んだ値と違う値になっている → 🚩
- 頼んだ箇所とは別の箇所が変わっている → 🚩
- 「だいたい合ってるけど、余計なことをしている」 → 🚩

## 🟡 PHP を触る人は、さらに

WordPress の PHP をAIに書かせたときは、以下も見ます。

| # | 見るところ | 何を確認するか |
|:--|:--|:--|
| ④ | **出力のエスケープ** | 画面に出す値に `esc_html()` / `esc_attr()` / `esc_url()` が付いているか |
| ⑤ | **入力のサニタイズ** | フォームやURLから受け取る値を `sanitize_text_field()` 等で処理しているか |
| ⑥ | **権限チェック** | 管理機能なら `current_user_can()` があるか |
| ⑦ | **nonce** | フォーム送信・Ajax なら `wp_nonce_field()` / `check_admin_referer()` があるか |

> AIは「動くコード」は書きますが、**「安全なコード」を必ず書くとは限りません。**
> ④〜⑦が抜けていても、画面上は正常に動いてしまいます。だから差分で見るしかありません。

## 通ったら

**コミットします。** メッセージには「なぜ」を書きます。

```
❌ 修正
⭕ 定休日の記載ミスを修正（水→木）
```

💡 コミットメッセージに迷ったら、**AIに「この差分を一言で説明して」と聞く**のもアリです。

---

## 通らなかったら

**戻します。** コミットしてあれば、1つ分だけ巻き戻せます。

> だから **「AIに任せる前に、まずコミット」** なんです。
> セーブしてからボス戦に行くのと同じです。
